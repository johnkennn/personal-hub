## 1. 产品定位（升级）

**一句话：** 给独立开发者 / 创作者的「作品展映平台」——用电影感页面把文章与项目讲成可传播的作品，而不只是又一个博客后台。

**产品目标：** 好用、可引流、可长期运营；后期可商业化。视觉保持深色工作室风，二期起在「展映」上做炫酷高潮。

**不是什么：** 不是重型社交网络，不是纯文档工具，不是只堆后台 CRUD。

---

## 2. 一期已锁定决策

| 项 | 决定 |
|----|------|
| 执行顺序 | 阶段 A → B → C → D |
| Mock 策略 | **仅**用于无数据空态提示，或接口失败时的**显式降级提示**；禁止静默假数据冒充线上 |
| 软删除 | 保留 **30 天** 后物理清理 |
| 作者回收站 | **不进一期**；建议二期/三期再做 |
| 开工入口 | 阶段 A（Studio 真接 + 头像/封面上传） |

---

## 3. 北极星功能（二期起重点）

### 作品展映（Showcase）

每个 **Project** 升级为展映页（全幅视觉、动效叙事、技术栈、Demo、关联文章作「制作特辑」）；创作者主页成为个人展厅；发现页强化「本周上映」与可分享 OG/卡片。

| 维度 | 理由 |
|------|------|
| 视觉 | 天然吃动效与全幅媒体，符合工作室风 |
| 引流 | 展映页 URL、分享图可外传 |
| 运营 | 专题周、精选展映 |
| 商业化 | 高级主题、自定义域名、置顶、容量与数据分析 |
| 继承 | 建立在一期 Project / Article / Media / Feed 之上 |

一期先把封面、真项目数据、真主页跑通，为展映种因。

---

## 4. 分期路线图

```text
一期  真可用底座（V1.1）
二期  作品展映成招牌（V2）
三期  增长与轻社区（V3）
四期  商业化与规模化（V4）
```

### 第一期 · 真可用底座（V1.1）

**目标：** 去掉演示双轨，主路径全真数据，可运维挂机。

| 阶段 | 内容 |
|------|------|
| **A** | Studio 接 `/api/me/articles|projects`；头像/封面 multipart；已发布不可编辑前后端一致 |
| **B** | 赞/评/关、通知铃铛、Feed/搜索、公开主页接真 API；去掉 social/activity 等 localStorage 主路径 |
| **C** | 管理台真治理（用户禁用、强制下架/删、评论）；去掉 `setDemoRole`；**管理仪表概览**；建议箱全接 API |
| **D** | 登录/注册/上传限流可配置；软删 **30 天** 定时物理清理；部署文档与 Flyway/HTTPS/JWT/CORS/health 对齐 |

**一期状态（2026-09-07）：已完成并打 tag `v1.1.0`。** 收口后惯例：提交 → 推送 → 打 tag → 部署服务器。

**一期成功标准**

1. 新环境按文档启动后，零静默 mock 可走完创作者与访客主路径。  
2. 管理台靠 JWT 真实 ADMIN 可运营，并有仪表数字。  
3. 限流、探活、30 天清理可配置可观测。

### 第二期 · 作品展映（V2）

**目标：** 因展映页好看、好晒而来并留下。

1. 展映页模板（分镜：故事 / 技术 / 演示 / 相关文章）  
2. 个人展厅时间轴 + 精选置顶  
3. 分享资产（OG、分享卡片图）  
4. 发现「本周上映」视觉流  
5. 文章 ↔ 项目关联（构建日志）  
6. Project 模型与媒体画廊扩展；品牌动效体系（少而精）

**成功：** 新用户愿意把展映页外发；回访看展厅而非后台。

### 第三期 · 增长与轻社区（V3）

1. 上映周 / 专题精选  
2. 展映页有意义反应（如「学到了」）与评论体验  
3. 关注动态卡片化  
4. 轻成就（克制）  
5. SEO / sitemap  
6. 可选：作者回收站  

**成功：** 周活扩展到「逛展映 / 追创作者」。

### 第四期 · 商业化与规模化（V4）

**创作者订阅（示意）**

| 能力 | 免费 | 专业版 |
|------|------|--------|
| 基础发布与基础展映 | ✓ | ✓ |
| 高级主题 / 动效包 | — | ✓ |
| 自定义域名 | — | ✓ |
| 媒体容量 / 画廊 | 有限 | 更高 |
| 展映数据分析 | 基础 | 详细 |
| 「本周上映」置顶权益 | — | ✓ |

另：反垃圾升级、OSS/Redis/观测、账号注销与数据导出、举报流程；更远可做团队展厅（B2B）。

**成功：** 付费强化品牌与曝光，不挡「发作品」核心。

### 明确后置（不进一～二期主线）

- 新内容模块（笔记 / 资源）  
- SSE 实时通知  
- 一期即上 Redis 分布式限流  
- 完整 Docker/K8s/CI（文档可先写清手工上线）  

---

## 5. 视觉策略

- **一期：** 接真数据，稳住交互与信息架构。  
- **二期：** 预算集中在展映页、发现大卡片、分享图。  
- 原则：一条主视觉高潮；2～3 个品牌动效反复使用，避免全站特效噪音。

---

## 6. 依赖关系

| 期 | 依赖 |
|----|------|
| 一 | 无 |
| 二 | 一期媒体 / 项目 / 主页必须为真 |
| 三 | 二期展映可分享、可发现 |
| 四 | 二、三有留存与差异化后再收费 |

---

## 7. 执行备注

- 教学与实现按阶段切片验收；每完成一块可提交。  
- 后端主路径（账号、内容状态机、社交、通知、Flyway、限流、健康检查等）已基本具备；一期重心是 **前端拆双轨 + 运营/工程收口**。  
- 本文确认后作为排期依据；变更需更新本文档版本说明。
